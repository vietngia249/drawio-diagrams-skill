# Shared presentation and serialization adoption assessment

Assessment against integrated baseline `33e9ad62cb50377cd07c1eb9f954c424a7c7a6d4`. Reference techniques were assessed independently; no reference code was copied. Current-source locations below identify the implementation reviewed.

| Reference technique | Existing implementation | Decision | Rationale and files | Verification |
| --- | --- | --- | --- | --- |
| Fixed example coordinates | Examples and fixtures use explicit coordinates; renderers also derive content dimensions and routed positions (`scripts/sequence.mjs:86`, `scripts/erd.mjs`, `scripts/geometry.mjs:229`). | Keep for examples only | Example coordinates are inspectable fixtures, not layout defaults to impose on semantic renderers. | Integrated renderer tests; inspect page-bound checks. |
| Entry-port-only routing | Shared router allocates source and target ports, tracks routes globally, and checks obstacles (`scripts/geometry.mjs:229`). | Reject as insufficient | Port selection alone does not route around obstacles or space parallel tracks. | `tests/geometry.test.mjs`. |

| Repeated bottom sequence headers | Sequence renderer creates participant headers at the top (`scripts/sequence.mjs:312`). | Defer | Bottom headers are a readability option, not required shared behavior; avoid duplicating labels by default. | Sequence fixture and Desktop image review. |

| Unicode labels | JSON and XML paths are UTF-8; existing tests cover valid code points and corrupted-source examples (`scripts/common.mjs:9-11`, `tests/shared.test.mjs`, `tests/fixtures/sequence/fittrackai-utf8.json`). | Keep source characters intact | Compare exact source string, XML-decoded value, and rendered image to distinguish source corruption from font fallback. | `Giao diện tiếng Việt` matched semantic JSON/XML and rendered with visible diacritics in Desktop PNG. |
